# 10.12 progress overview

## Desktop app: Windows build, and catching up to what's on main

**Where things stood.** The latest installer, 1.7.3 (2026-10-06), is missing ten desktop commits that are already on `main`: dual-stream recording, ONVIF multi-profile support, high-res clip trim and re-upload, scanning every local subnet, end-of-day footage expiry, and several fixes to those. Nobody has a build with them. There was also no Windows build at all.

**What changed (branch `feature/windows-desktop-build`, not yet merged).**
- A Windows x64 installer (unsigned) is now built by CI on every PR and published to the same release as the Mac DMG on a `desktop-v*` tag.
- One real Windows bug fixed: stopping a recording used a signal that Windows turns into a hard kill, which is the corruption case from ADR-031. Windows now asks ffmpeg to finish its file by writing `q` to it.
- Install instructions for Windows are in `desktop/README.md`.

**Not verified yet.** Nothing has been run on a Windows machine. The Linux test suite passes (336 tests); the Windows CI job is the first real Windows run, and a camera test on a real Windows PC is still needed before handing it to a venue.

**Next.** Merge this, cut 1.8.0 from the merged commit (picks up the ten commits above), and test the installer on a Windows PC with a real camera.

## Seeing which venues are behind (PIC-222, step 1 of remote updates)

**Why.** With unsigned builds every update is manual, and the console could not tell which venue runs which app version — its heartbeat only carried camera firmware.

**What.** The desktop heartbeat now also reports the app's own version and platform; the console shows both in Overview > Connected agents and marks agents behind the newest published release. An older app that reports nothing shows "Not reported", and an unreachable GitHub shows no marker — never "up to date".

**Status.** Built and tested, not shipped: console change is on a branch awaiting review on staging (and the migration must be applied before it reaches production); the desktop half rides the next desktop release. Remote/automatic update itself is parked as PIC-223 — Windows could do it unsigned, macOS cannot until signing (PIC-117).
