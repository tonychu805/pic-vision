# 2026-08-24

## First end-to-end pipeline run on brand-new footage, and a real "is this broadcast footage" scare that turned out fine

Operator handed over a genuinely new video — `Brick-Wall--Mid-Atlantic.mp4` — and asked for the full pipeline run start to finish, ending in a highlight reel. Different from yesterday's `brickwall-SEMI` work: no hand labels exist for this one, so this tested the *operational* pipeline (does it run cleanly, does the output look right), not detection accuracy.

**Real scare, resolved carefully rather than assumed away.** The file's provenance (a matching download in `~/Downloads` named `YTDown.com_YouTube_Brick-Wall-Pickleball-Mid-Atlantic...`) pointed straight at YouTube — and this project already archived two YouTube broadcast videos as unusable (19–25 hard scene cuts per 3 minutes, `progress/08.18 progress overview.md`). `check_drift.py` alone wasn't trusted as sufficient to clear it (its averaging could plausibly mask many cuts that happen to cancel out) — pulled frames at four points spread across the 21-minute video and confirmed identical framing throughout, including the same tripod-mounted phone visible in every shot. Genuinely a single fixed-camera recording someone uploaded to YouTube, not an edited broadcast. Worth remembering: **file origin (YouTube, an unusual filename) is a legitimate reason to double-check even when the automated drift tool says stable** — it wasn't built with hard-cut detection specifically in mind.

**Pipeline ran clean end to end:** decode integrity checks (before and after), 25→30fps CFR conversion, operator-clicked calibration (0.283ft RMSE — calibration stayed a human-in-the-loop step, per `STRATEGY.md`'s explicit "never blind auto" stance), local-GPU TrackNet inference (~24 min), detection (56 candidates), ranking (`src/select.py`'s locked ADR-063 formula), and a 12-clip, ~4:58 reel — both chronological and rank-ordered versions.

**One real bug, caught by checking rather than assuming:** generalizing `scripts/rank_and_reel.py` for reuse (previously had `brickwall-SEMI` hardcoded) silently dropped the call that builds the chronological `highlight.mp4` — only the ranked version was actually written. Found by verifying both output files exist before calling it done, not by trusting the script ran correctly. Fixed and reverified.

**Reviewed by frame sample, not yet full playback.** Pulled one mid-clip frame per clip (all 12) plus both boundaries of the top-ranked clip — every clip shows genuine active rally play, boundaries land on natural pre-serve/post-point moments. Explicitly **not** a final verdict — this project's own rule is that stills-based verdicts have been wrong before (`IMG_7744` FP review). Full playback review, especially of the shortest/lowest-ranked clip that made the cut (#12, 7.1s), is the next thing to actually do, not done yet.
