# 10.30 progress overview

## Badge pose speed experiments

Tested pose batches 8/16/32, reduced input size, and YOLOv8n on the RTX 2000 Ada. Batch 16 did not materially speed up inference; batch 32 was slower. YOLOv8n was much faster but changed pose and badge measurements substantially. A full blind 42-rally brickwall comparison of YOLOv8x at 640×1120 showed an approximately 27% pose-time saving, but changed two of three awarded badge locations and added a different badge. Keep production at YOLOv8x 736×1280, batch 8; the reduced input is not acceptable for current badge behavior (ADR-163).

The full comparison is recorded in `EXPERIMENTS.md`; see ADR-161 through ADR-163 for the decisions and evidence.

### Staging speed trial complete

Ran the full Lifetime Fall Classic 1080p60 source through the real staging pipeline with YOLOv8n at 736×1280, batch 8 (staging branch commit `798c065`). Badge pose took 192 s for 11,096 frames (57.8 fps); the whole single-job flow took 13:25 from queue update to completion. It measured 290 swings across 30 rallies and awarded Kitchen War and Hardest Swing. The run has no same-run YOLOv8x baseline, and the cloud GPU type and bill were unavailable, so it establishes successful staging execution and one speed measurement, not badge parity or a production recommendation. Details and the staging share link are in `EXPERIMENTS.md`. Production remains YOLOv8x at 736×1280, batch 8.

### Five-part staging replay

Replayed the 720p30 Lifetime Fall Classic source as four five-minute parts plus a 102.7-second final part, uploading each at its game-clock boundary through the staging agent API. YOLOv8n pose took 37–43 seconds for each full part (165.8 seconds across all five). Four parts were ready within 8:34 of recording end, but part 2 required three jobs after repeated stuck pod starts and GPU capacity failures; the complete set was ready **17:08 after recording end**. The agent access could not create a fresh recording session, so this run used separate jobs and did not exercise warm-machine reuse or the single player share. Combined measurements produce a different hypothetical badge set from the historical YOLOv8x replay. See `EXPERIMENTS.md` for the per-part timings and links. A console-issued shared session is still needed for a production-path timing comparison.
