## PIC-6: labelling self-consistency measured for the first time — presence, not boundaries, is the real noise floor

- Blind-relabelled the prepped 5-minute clip (`videos/IMG_7743_consistency_0-300s.mp4`), a day after prep as planned. 5 rallies originally, 7 on the blind repeat, only **3 of 9 distinct rally-windows agreed on by both** (2 missed on repeat, 4 found that weren't marked the first time).
- Boundary spread on the 3 agreed rallies is small (~0.6s median) — close to the project's own ±0.5s target, not the concern.
- **The bigger, previously-unmeasured source of noise is whether a stretch counts as a rally at all** — roughly a third agreement, bigger than several of the fine precision/recall differences chased the previous day (e.g. PIC-43's `min_crossings=6` vs `7`, ~0.05 precision). Doesn't invalidate that day's conclusions, but any comparison finer than roughly this margin should be read with real skepticism.
- One data point (one labeller, one 5-minute stretch) — not a precise constant. Feeds directly into PIC-39 (adversarial review, below).
- Recorded in `EXPERIMENTS.md`, `LABELING.md`. PIC-6 closed. The corrected re-run, **PIC-44**, is a separate open issue — clip ready at `videos/IMG_7743_consistency2_1270-1570s.mp4`, not yet run.

## Later: PIC-39 adversarial review blocks the label-artefact numbers (ADR-053); court_wedge wired into src/cut.py's CLI

- **Ran the project's formal adversarial-review process** (skeptic, red-team, simplifier, independent, majority-survives) against the precision-ceiling-artefact conclusion from 2026-08-19. All three REFUTED — unanimous, not a majority-block.
- Each lens found something concrete and different: skeptic measured a boundary-anchoring gradient (precision 0.29→0.45→0.54 as ground truth moves from independent to detector-anchored); red-team found the relabelling process is structurally monotone (can only ever raise precision, since it draws candidates exclusively from the detector's own false positives and only adds labels, never removes or discovers ones the detector missed entirely) and that the project's own required chance-adjusted-lift check, run for the first time, goes the wrong way on 2 of 3 videos; simplifier traced 3 of PIC-6's "extra" blind-pass rallies to detector candidates that were never merged in.
- **Retraction survives, replacement doesn't.** "0.25–0.29 isn't a hard detector ceiling" still holds (independent support: the 2026-08-09 curated-label habit, brickwall's fragment finding). "0.44/0.54/0.59/0.64 are trustworthy detector-quality numbers" does not — the one label set made without seeing detector output (PIC-6's blind pass) scored the detector *worse* than the number everyone was trying to move past.
- Also found and flagged, not yet fixed: a silently corrupted label file (nested duplicate ground truth on IMG_7744) and an unguarded `merge` that overwrites committed ground truth in place with no backup.
- Recorded as **ADR-053**. `CHECKLIST.md`/`EXPERIMENTS.md` annotated provisional — every precision/recall number from before this date should be read as provisional until re-validated.
- **`/committee-review` (formerly `/gemini-review`) gained a third reviewer, Kimi K3, alongside Gemini and Claude.** Run against the full codebase (not a diff), it found that `src/cut.py` — the actual `make process` CLI entry point — never wired `court_wedge`, despite `court_wedge` being cited as "shipped config" in every scoring entry since ADR-048. The CLI had silently been using the older flat gate the whole time. Fixed, 101/101 tests, and validated against cached dev footage (not `eval`): no cost on brickwall, a real gain on pb_draft_cup, and a large one on IMG_7744 (adjacent-court-noise camera), precision 0.197→0.54–0.62 depending on `margin_px` (left at its unexamined default, flagged rather than tuned). Closes PIC-40. Same review pass also caught two stale scripts, now moved to `archive/`: `scan_crossings.py` (broken import, `ImportError` on any run) and `debug_detections.py` (ran fine, but visualized the retired YOLO detector, not TrackNet — silently misleading if used to debug the active pipeline). `calibrate_web.py`'s unused `threading` import and write-only `STATE["saved"]` also removed. Full detail: `EXPERIMENTS.md` 2026-08-20 "court_wedge wired into src/cut.py" entry.

Real pretrained badminton weights exist that could be fine-tuned instead of training from scratch (MIT-licensed code), but the weights' own usage terms are undisclosed — needs asking the authors before relying on it for anything beyond prototyping.
