# 09.29 progress overview

## Design review: how the venue machine talks to the console

The basic shape holds up: the machine only ever connects out, a push is only a "go check" signal, the 60s poll is always underneath it, and every wait has a time limit. Seven findings, two fixed today:

- **Fixed — the instant command channel after a first sign-in.** A fresh install registers as part of signing in, and nothing started the fast command channel there, so a new venue's first Calibrate waited on the 60s poll until the app was restarted. Sign-in and sign-out now both rebind it. Tested; not yet watched on a real sign-in.
- **Fixed — three console routes checked the machine's token their own way** (heartbeat and both command routes), skipping the "this machine was removed" check. Safe today only because removing a machine also clears its token. They now use the shared check, and a new test fails if any route goes back to doing it by hand.

**Still open, in priority order:**

1. ~~**Anyone can take over another venue's machine if they know its device ID.**~~ **Fixed, not yet live (ADR-134).** The console now only looks for a machine inside the signed-in account. A machine signed into a second account gets its own separate record there, and the first account's record is left alone. The cost: **camera calibrations don't follow an account switch**, so set up a venue's machine signed in as the venue. Waiting on: the database change, then the console push.
2. **A booked recording only stops if the internet is up, and old commands never expire.** If the venue drops offline mid-booking, it keeps recording. A start queued while the machine was off runs whenever it comes back, possibly hours later. Fix idea: the start carries its planned stop time and the machine stops itself; commands get a "valid until".
3. **A command can run twice** if its result report is lost (for example, a start shows as failed while the camera is recording).
4. **A machine the console has rejected just says "Connection lost"** and retries forever, looking the same as a Wi-Fi drop.
5. **Removing and re-adding a camera deletes its calibration**, because the console hard-deletes camera rows missing from the heartbeat and the calibration lives on that row.

**Not pushed:** the desktop change is in `pic-vision`, the route change in `pic-vision-cloud-console`. Both are committed only.
