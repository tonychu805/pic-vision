# 2026-10-27 progress overview

## Production incident: share-page videos blocked for ~5 hours (fixed)

**What players saw.** From **03:19 to ~09:05 UTC (11:19 AM – ~5:05 PM Taiwan)** every production
share page loaded but **no video played**.

**Cause.** pic-vision-reel PR #9 (signed 1-hour video links from the private bucket, ADR-142)
merged and deployed at 03:19 (`df50738`). The page now loads videos from the R2 account
endpoint and refreshes the links from the console, but its Content-Security-Policy still
allowed only `cdn.picvisionai.com`, so browsers refused every video. Staging had caught exactly
this the same day and the fix (`bc1b260`) was pushed to the PR's branch — **after** the PR had
already merged, so it never reached `main`.

**Fix.** PR #10 (`f35bf69`, a cherry-pick of `bc1b260`) adds the R2 host to `media-src` and
`connect-src` and the console origin to `connect-src`. Verified live after the merge: the
production CSP carries both, a 09-25 page's 32 signed videos all answer 206 `video/mp4` with
CORS for `share.picvisionai.com`. Operator phone check pending.

**Follow-up / gate.** A fix pushed to a PR branch after merge silently goes nowhere. Before
merging a share-site or console PR that changes where media loads from, check its staging
verdict is on the exact commit being merged. Not automated yet (owner: operator).

## Netlify could not clone the private console repo (fixed)

From 07:18 UTC every picvision-console build failed at "preparing repo" with *Repository not
found* (public repos like pic-vision-reel kept building, needing no credentials). GitHub's
security log showed nothing revoked; re-linking didn't help. **Re-saving the Netlify GitHub
app's repository access** (switch to "Only select repositories" with the console, share and
website repos) fixed it. Production was never affected: it stayed on `cca5264`.
