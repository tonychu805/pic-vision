# 10.17 progress overview

## Glare filter: what we learned and what we decided (ADR-154)

Wraps up yesterday's bounce and glare work. Detail: `DECISIONS.md` ADR-154 and `EXPERIMENTS.md`
2026-10-16 (Test E2 and its follow-up).

- **Learned:** fixed shiny spots (a court reflection, a white object on the back shutter) are the
  main reason ball tracking fails on glare courts. On a court without glare, today's bounce finder
  gets 35%, close to the 40% goal.
- **Learned:** the new filter removes almost all the glare and every glare fake rally, but slow
  balls (soft bounces, a ball rolling to a stop) look like glare to it.
- **Learned:** all 4 real rallies it lost were on one glare court, where today's system was partly
  following glare already; two of those rallies were found by luck. Clean courts lost none.
- **Decided:** the filter stays off. Nothing in the product changes.
- **Next, if pursued:** switch it on only for courts with measured glare, and only remove spots that
  stay lit for minutes, not seconds. Test on fresh footage (all three labelled stretches are now
  used up). Tracked in Linear as PIC-231 (summary comment on PIC-226).
- **Separate problem:** on the worst glare court the ball itself is hard to see; a filter can't fix that.

## Can we retrain TrackNet ourselves? Yes, technically

- Loaded the production weights (k14, from the public TrackNet-Pickleball project) in the existing
  TF 2.15 environment and ran 3 real training steps on made-up data on the local GPU (RTX 2000 Ada,
  16 GB): gradients reach all 54 weight tensors, the weights change, and the saved model reloads and
  gives identical output. About 0.2 s per step of 2 samples, so a few thousand labelled frames
  over ~30 passes is an overnight run on this machine, no pod needed.
- Model shape: 3 frames in (9 x 288 x 512), one ball heat-map per frame out. Its loss function is
  already in `scripts/pod_infer.py`. No training script in the repo yet; it would be ~100 lines.
- Missing: frame-by-frame ball labels (our bounce labels are one point per landing, not usable).
  Labelling can start from k14's own detections in CVAT, so the operator only fixes mistakes
  (deletes glare marks, adds missed balls) instead of clicking every frame.
- Risk: we don't have the original training data, so fine-tuning only on our courts could make it
  worse elsewhere. The existing labelled rally and bounce sets are the check for that.
- Permission to train on PGC footage set aside by the operator for now (PIC-190 still open).
