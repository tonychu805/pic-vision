## Accounts: venue owners and players (checked 2026-11-16)

Source: Supabase security advisors on production, the function bodies, and the console/share code.

### P0 — fix now: anyone can list every game at a venue

`get_demo_sessions_by_slug_code` and `get_demo_sessions_by_share_id` (the demo-admin date picker) are `SECURITY DEFINER` and executable by `anon`. The demo-admin password is checked only in the share app's `/api/admin/sessions`, which then calls the function with the **public anon key**. So anyone with a venue's address (printed on every court poster) or one clip link can call the database API directly and list every game on any date, with clip links: it bypasses the password and the "players see only their own games" rule. **Confirmed on staging as `anon`** (3 games, 3 links, no password); production runs the same code, not tested there.

Fix (one console migration + one share-app change, staging first):
1. `revoke execute ... from public, anon, authenticated` on both; drop `get_demo_sessions_by_share_id` (unused).
2. `/api/admin/sessions` calls it with a server-only service-role client after the password check (needs `SUPABASE_SERVICE_ROLE_KEY` on the share site, server side only).
3. Check on staging: as `anon` the call is refused; the demo picker still works after the admin login.

## Keep it secure afterwards (guardrails)

| Guardrail | What | Why |
|---|---|---|
| Weekly dependency scan in CI | `pnpm audit --prod` / `npm audit --omit=dev` / `pip-audit` per repo, failing on critical | this scan was manual; 3 criticals sat unnoticed |
| Security update PRs | Dependabot or Renovate, security updates only | fixes arrive as reviewable PRs |
| SBOM per release | regenerate `sbom/` with each desktop release and each web-app upgrade | keeps the inventory true |
| Desktop minimum version | console tells old desktops "must update" (see memory note on update guardrails) | old installs keep old Electron, and ≤ 1.11.1 lacks the 30-day cleanup |
| Pod image scan | scan the GPU pod's container image (OS packages) | not covered by this scan |
| Supabase advisors | review the security advisors for both projects each release | database-side checks; the P0 above was found this way |
