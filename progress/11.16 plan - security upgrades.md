# 11.16 plan: security upgrades

From the 2026-11-16 scan (`sbom/VULNERABILITIES.md`). Goal: no known critical or high finding in anything that runs for players, venues or the operator, without breaking a live service.

**Rule for every step:** staging first, one component at a time, a named check before merge, a rollback ready. Nothing in steps 1–4 changes cameras, recording or the GPU pipeline.

## Steps

### 1. Desktop 1.12.0 with Electron 44.11.3

- Bump `electron` to 44.11.3; `npm audit fix` (non-forced) for build tools; update the bundled Node/Chromium versions in the desktop SBOMs (`sbom/VULNERABILITIES.md`, manual step).
- Checks: `npm test` (lint + 420), CI macOS + Windows build, then a **manual release-candidate build** (`workflow_dispatch`) — the earlier 1.12.0 candidate is replaced.
- Operator: install the candidate on a Mac (colors, venue language, version 1.12.0); then **at Syno**: camera found, live view, a short check-in recording, clips arrive.
- Release: tag `desktop-v1.12.0` on the tested commit. Venues update when someone installs it.
- Rollback: venues keep 1.11.1 until they install; a bad release is fixed by 1.12.1.

### 2–4. Web apps: Next.js 16.4.6

Per app, one PR:
- `next` 16.3.3 → 16.4.6 (and `eslint-config-next` if pinned to it); move `shadcn` to `devDependencies`; console also refreshes `posthog-js`.
- Checks: `tsc`, unit tests, browser tests (share app), `next build`, then on the staging site:
  - website: home, /privacy, /non-user-privacy, venue notice template;
  - share app: sign-up (email, LINE, Google), consent box, profile, check-in → end → claim, leave, highlights, a clip page incl. vertical, account page;
  - console: sign-in/up with language, overview, cameras, settings (QR page, posters, language), reels, a desktop heartbeat and a reel job end to end on staging.
- Re-run `pnpm audit --prod`: the three criticals and the `shadcn` chain gone.
- Merge = Netlify production deploy. Rollback: Netlify "publish previous deploy" (one click) or revert.

### 5. Orchestrator build tools

- `npm audit fix` in `orchestrator-worker`; `npm test` (89); deploy to staging (`wrangler deploy --env staging`), one staging reel job; then production deploy. Rollback: `wrangler rollback`.

### 6. electron-builder major

- Separate, after 1.12.0 is out: the breaking build-tool upgrade, checked by unpacking the DMG/EXE (bundled ffmpeg, app runs) as in the 09-07 packaging checks. Ships as the next desktop release.

## Keep it secure afterwards (guardrails)

| Guardrail | What | Why |
|---|---|---|
| Weekly dependency scan in CI | `pnpm audit --prod` / `npm audit --omit=dev` / `pip-audit` per repo, failing on critical | this scan was manual; 3 criticals sat unnoticed |
| Security update PRs | Dependabot or Renovate, security updates only | fixes arrive as reviewable PRs |
| SBOM per release | regenerate `sbom/` with each desktop release and each web-app upgrade | keeps the inventory true |
| Desktop minimum version | console tells old desktops "must update" (see memory note on update guardrails) | old installs keep old Electron, and ≤ 1.11.1 lacks the 30-day cleanup |
| Pod image scan | scan the GPU pod's container image (OS packages) | not covered by this scan |
| Supabase advisors | review the security advisors for both projects each release | database-side checks (RLS, exposed functions) |
