# 11.03 progress overview

## Labeling practice audited across the whole project — tentative framework agreed, not yet built

Prompted by asking whether the 11/1 PDSC staging reels were "rated" (they weren't — ranked by the detector's own score only, no human has watched them). That led into auditing every way this project has ever collected a label, since the ranking score traces entirely back to ball detection and the fine-tune meant to fix Court 3's detection gap has never had its recall measured.

**What exists today, verified directly (not taken on faith from the first pass that found it):**

- **Rally presence/quality has three separate, disagreeing systems**, none aware of the others: `label.py`/`label_web.py` (committed, canonical — but its grade pass can `splice()` a presence row out entirely with no record), a scratchpad `labels.json` (45 `verdict`-bearing keys across two detector-config sweeps, only 29 ever exported to `eval/labels/pdsc_court3_20261101_rally_verdicts.jsonl`), and a CVAT project (`scale-dropped-review`, 16 `real_rally`/`not_a_rally` verdicts) that neither the first audit pass nor my own first CVAT query caught, because it stores tags on `engine_labeledimage`, not the shapes/tracks tables we'd queried.
- **CVAT holds real ground truth across four label kinds, all first-hand counted from Postgres**: 200 bounce points (confirmed — the original external audit's "209" was wrong, this project's own `FOOTAGE_INVENTORY.md` had it right), 100 hit points, 96 serve-contact points, plus three tile-review projects judging candidate detections. One project (`bounce-chunk2-overlay`) was wrongly logged as "0 annotations" by both the external audit and this project's own inventory — it actually holds 15 tag annotations (`glare_mixed`/`tracked_fine`), just stored differently than the bounce-point projects.
- **The CVAT round-trip already exists** — `scripts/cvat_to_bounce_labels.py` and five sibling export/review scripts — but it, the 100 hit labels, most of the bounce labels, and the scripts themselves all live only on `feature/bounce-labelling`, a local branch 156 commits ahead of `main`, last touched 2026-10-19, never pushed to `origin`.
- **CVAT's Docker volumes have no backup of any kind** — checked `crontab -l`, looked for `restic`/`borg`/`rclone`/`syncthing`, none installed. Every bounce/hit/serve label above is a single `docker volume prune` away from gone.
- **Three ad-hoc web labelers** beyond `label_web.py`, each a fresh `http.server` + hand-rolled HTML: `label_bounce_web.py` (blind bounce labeling, to measure what the detector misses — 18 real rows, also stranded on the unpushed branch), a multi-page server on port 8791 (`top10.html`/`badges.html`/`serve.html`/`cuts.html`/`dots.html`/`rallies.html` — the full PDSC Nov-1 judging pass, 480 keys, one shared `labels.json`), and a view-only swing/spike/serve viewer on port 8451 with no save hooks at all (verdicts went through chat, never a file).
- Killed two confirmed-orphaned label servers (ports 8767, 8451 — processes 19 and 7 days old). Left the port-8791 server running: its scratchpad directory belongs to a different session ("PDSC staging runs data quality") that's offline but not confirmed finished.

**Tentative framework agreed, not yet implemented:** one canonical schema *per label kind* (rally_presence, rally_quality — kept as separate files so a grade pass structurally can't delete a presence row — bounce, hit, serve), written as flat `eval/labels/<kind>/<source>.jsonl` files, not a database (the project already commits labels this way, and a database would just repeat the CVAT backup gap). Every row carries a stable `id` (never renumbered), an explicit time origin (not smuggled into the filename), and a provenance block (tool, operator, source config). Any collection surface — CVAT, an extended generic mode on `label_web.py`, or a one-off scratch UI — can keep existing, as long as it writes this shape. The index (today split across `sessions.jsonl` and `FOOTAGE_INVENTORY.md`, both independently stale) gets generated from the files themselves instead of hand-maintained.
